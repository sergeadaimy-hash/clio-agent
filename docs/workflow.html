01

One Event Day

Submissions bucket by local date in the configured timezone (default Asia/Riyadh). Both cron times come from schedule_config; saving the Schedule section restarts the jobs immediately.

00:00 · Day opens

New reporting date

The date bucket rolls over at local midnight. Portal, reminders, and the nightly report all key off this one date string.

today() · luxon · TIMEZONE env

All day

HOD submissions

Three-step portal: progress, notes, photos with captions. Each text field is polished in-browser via Claude Haiku before submit; on any API error the original text passes through untouched.

Resubmits merge photos and captions and bump the version.

POST /api/submit · POST /api/review-text

Per submission

Confirmations fan out

The HOD gets an email and WhatsApp receipt. The PM list gets an email with the status text, highlights, blockers, and the live submitted-versus-pending roster.

notifyHodSubmissionConfirmation · notifyPmOnSubmission

21:00 · Reminder cron

Nudge the stragglers

Email plus WhatsApp, sent only to departments that have not yet submitted. Each send is logged to the audit trail. Admin can also fire this manually, per department or for all.

sendPendingReminders() · reminder_sent

23:00 · Report cron

Deck generation

A Python process reads SQLite directly and builds the branded PPTX. Runs for the same date are serialized behind a per-date lock so preview renders and the nightly job never tear the file.

generate_report.py · reports/{date}/daily_report.pptx

23:00+ · Delivery

Two exits

OKReport emailed to the PM list with the PPTX attached, plus a WhatsApp ping to PM numbers.
FAILError email to PMs with the full raw submission JSON dump, so no data is stranded. Logged as report_failed.

Fail-soft is the house rule: every notification, every WhatsApp send, and the LLM polish are wrapped so a failure logs and moves on. Nothing in the notify path can block a submission or the nightly report.

02

Actor Map

Who talks to what. Solid lines are direct HTTP; the dashed frame is the deployment boundary planned for Railway.

HODFiles the daily report from a phone: three-step portal, photo captions, edit until the deadline. Also chats on WhatsApp, where reminders and receipts land.
AdminRuns the console: Overview, Departments, WhatsApp, Brand, Report, Delivery, Schedule, Archive, Project. Sends nudges, triggers decks, takes over WhatsApp threads.
CLIO agentClaude Haiku behind two jobs: polishing HOD text field by field, and auto-replying to inbound WhatsApp. Replies are capped at 5 per thread per day and 50 per day globally, and any thread can be switched to human mode, which silences the agent for that conversation.
PM teamPure email recipients, managed from the Delivery section. They get per-submission updates, the nightly deck with attachment, and failure alerts with the raw data.
Meta webhookInbound messages and delivery statuses arrive on a webhook verified two ways: a token handshake on GET and an HMAC SHA-256 signature check on every POST. Duplicate deliveries are dropped by message id.
Railway hostPlanned deployment target. The DB, uploads, and reports all resolve under a single DATA_DIR so one mounted volume carries the whole state.

04

Data Stores

One SQLite file plus two file trees, all resolved under DATA_DIR when set (the Railway volume) and under the app folder otherwise.

departments

The reporting units: HOD contact details, stream color, and a one-level parent_id hierarchy for grouped streams.

daily_submissions

One row per department per date: progress, texts, schedule, photo paths, captions, polished variants, version counter.

submission_log

Append-only audit trail: submits, reminders, settings changes, report runs and failures.

settings

Key-value JSON blobs: event identity, brand_config, report_config, pm_emails, delivery_config, schedule_config.

whatsapp_threads

One per phone number: linked department, display name, unread count, and the per-thread agent / human mode.

whatsapp_messages

Every message in and out: direction, sender (system, agent, human), template name, Meta message id, delivery status.

uploads/

uploads/
├─ {date}/
│  └─ {DEPT_SLUG}/
│     └─ *.jpg          photos, HEIC re-encoded
└─ brand/
   ├─ logo.png           admin-uploaded logo
   └─ report_template.pptx  imported deck template

reports/

reports/
└─ {date}/
   ├─ daily_report.pptx  the nightly deck
   └─ preview/
      └─ {confighash}/
         └─ slide-NN.png rasterized preview cache

DATA_DIR indirection: db/clio.db, uploads/, and reports/ all derive from one env var, so mounting a single volume at /data on Railway persists the entire system state. The Python generator resolves the same paths independently.

05

Flagged Weak Spots

Known gaps, verified against the code, ranked so the highest-value fixes surface first. None of these block day-to-day use today.

HIGH
SQLite on a single volume with no backup job
All state lives in one clio.db plus file trees; losing the volume loses the event history.
nightly copy to object storage, or Litestream replication
MEDIUM
Admin auth is one shared password on every request
No sessions, no roles, no expiry; anyone with the string is fully admin forever.
session tokens + per-user accounts before multi-admin use
MEDIUM
Archive and preview image URLs carry the admin password in the query string
Needed because img tags cannot send headers, but the password lands in browser history and server logs.
short-lived signed URLs for image serving
MEDIUM
Meta test-number access token expires roughly every 24 hours
Operational burden: WhatsApp silently degrades to fail-soft skips when the token lapses.
permanent system-user token + a registered message template for production
MEDIUM
req.ip needs trust proxy on Railway
Behind Railway's proxy every request shares one IP, so the per-IP review-text limit collapses to a single bucket.
app.set('trust proxy', 1) in the deploy task, already planned
MEDIUM
Weekly generator predates the v2 work
generate_weekly_report.py hardcodes Calibri, ignores template mode, and does not order by hierarchy. Matters only if weekly reports are used.
port the daily generator's brand, template, and ordering logic
LOW
Review-text rate limiter never evicts stale IPs
Hit lists are pruned per IP, but old keys stay in the map forever: bounded per IP, unbounded keys.
periodic sweep, or an LRU with a max key count
LOW
Preview PNG cache accumulates stale confighash dirs
Every report-config change mints a new hash directory under reports/{date}/preview and nothing prunes the old ones.
keep only the newest hash per date, delete siblings on render
LOW
Light-background templates render token-colored text poorly
Imported templates keep CLIO's light text tokens, which vanish on white slides; adopting the theme's text colors is a follow-up.
derive text color from the template theme in template mode
LOW
report_config saves wholesale, so concurrent admins can clobber each other
The whole JSON blob is written on save; two open sessions overwrite each other's template settings silently.
merge on write, or a version field with a conflict warning
LOW
WhatsApp timestamps are UTC while the app buckets by Asia/Riyadh
Inbox shows browser-local times, and agent reply caps reset at UTC midnight instead of the event's midnight.
store or window timestamps in the configured timezone
LOW
Portal favicon and theme-color meta are hardcoded defaults
Both pages ship the slate-and-blue mark regardless of the brand configured in the admin.
emit favicon and theme-color from brand_config
